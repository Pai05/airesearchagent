## Critical integration rules — read these before writing any code

These rules exist so that when your pipeline connects to the frontend
everything works automatically without the integrator having to fix anything.

RULE 1 — Your output shape must exactly match shared/schema.py
The frontend is already fully built against this exact shape.
If you add, rename, or remove any field the frontend breaks silently.
Do not change any field name. Do not add extra fields.

RULE 2 — Always sort by published_date descending before returning
The frontend expects the newest papers first.
This sort must happen after dedup and validation.
published_date format is always YYYY-MM-DD.

RULE 3 — landing_url must never be None or empty on any paper
This is the fallback link the frontend shows when there is no PDF.
If a paper has a DOI use: https://doi.org/{doi}
If a paper has no DOI use the arXiv abstract URL or Semantic Scholar URL.
A paper with an empty landing_url will show a broken button in the frontend.

RULE 4 — Never call the LLM on a paper with an empty abstract
If abstract is an empty string set findings=[] and gaps=[] and skip it.
Do not send an empty string to the API.

RULE 5 — Always check the cache first before any LLM call
Use get_cached(paper_id) from backend/cache.py before building any batch.
If the result is already cached use it directly.
This saves money and makes repeated searches instant.

RULE 6 — findings must always be a list — never a string or None
Even if extraction fails set findings=[] not findings=None or findings=""
Same rule applies to gaps.
The frontend loops over these arrays — a non-array value will crash it.

RULE 7 — Return a minimum of 40 papers after dedup
If your combined fetch returns fewer than 40 after dedup
tell the integrator immediately and do not continue.

RULE 8 — citation_count must always be an integer — never None
If the API returns None for citation_count set it to 0.
The frontend sorts by this value — None will break the sort.

RULE 9 — year must always be an integer — never None or a string
If the API does not return a year extract it from published_date.
published_date[:4] gives you the year as a string — convert with int().

RULE 10 — source must always be exactly one of these two strings
"semantic_scholar"
"arxiv"
Never use abbreviations, capitals, or any other value.

## The paper object you must output

Every paper your pipeline returns must have all of these exact fields.
A paper missing any field will cause the frontend to break.
Use shared/schema.py as your reference at all times.

id: string — generated by make_paper_id() from backend/dedup.py
never generate this yourself
title: string — never None, use empty string if missing
authors: list — list of name strings, can be empty list
year: integer — four digit year, never None
published_date: string — YYYY-MM-DD format, never None
doi: string — can be None if paper has no DOI
source: string — "semantic_scholar" or "arxiv" only
abstract: string — can be empty string but must exist as a field
pdf_url: string — can be None, frontend handles this
landing_url: string — NEVER None or empty, always provide a URL
is_open_access: boolean — True or False, never None
citation_count: integer — use 0 if unknown, never None
findings: list — list of strings, use [] if not extracted yet
gaps: list — list of strings, use [] if not extracted yet
field_tags: list — list of strings, can be empty list

## Task 2 — Build the LLM extractor

This is your main task. Create pipeline/extractor.py

What it must do:

- Accept a list of paper dicts and a topic string
- For each paper check get_cached(paper_id) first
  If a cached result exists use it and skip the API call for that paper
- For papers not in cache and with a non empty abstract
  build a batch request to Claude Haiku
- Send all uncached papers in one single batch call
  using client.beta.messages.batches.create()
- Poll the batch status every 5 seconds until
  processing_status equals "ended"
- For each result parse the response as JSON
  extracting "findings" and "gaps" keys
- Save each result to cache using save_to_cache()
- If JSON parsing fails for any paper
  set that paper's findings=[] and gaps=[]
  do not crash the entire batch because one paper failed
- Set paper.findings and paper.gaps on every paper in the input list
- Return the full papers list with findings and gaps filled in

The model to use:
claude-haiku-4-5-20251001

The max_tokens to use:
300

The prompt to use for each abstract — use this exactly:
"You are a research analyst. Given this abstract extract:

1.  Three key findings (specific results not general descriptions)
2.  Two explicit or implied research gaps
    Return ONLY valid JSON no explanation no markdown:
    {\"findings\": [\"...\", \"...\", \"...\"], \"gaps\": [\"...\", \"...\"]}
    Abstract: {abstract}"

Truncate the abstract to 1500 characters maximum before sending.
Never send more than 1500 characters.

After writing the file push it:

```bash
git add pipeline/extractor.py
git commit -m "add LLM extractor"
git push
```

Then tell the integrator: "extractor.py pushed, ready to test."
